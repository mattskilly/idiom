What it catches

The things a person notices in the first minute.

Accessibility linters and screenshot diffs pass all of these. Each card shows a real finding from Idiom's own test screens: a crop of the problem, what is wrong, and when it counts as fixed.

major dead-control

A button that does nothing

“Name this version” is enabled, but clicking it changed nothing: no DOM change, focus move, navigation, dialog or network request.

Done when Clicking it shows a result, or it is disabled with a reason, or it is removed.

major unexplained-control

An icon nobody can read

A control labelled only “?” with no tooltip and no name that says what it does.

Done when A tooltip on hover and focus names what it does.

minor text-centering

A label sitting low

“Button” sits 2px below the vertical centre of its 28px chip.

Done when The label sits within 1.5px of centre.

major adjacent-gap

Controls touching

The message field and Send sit 0px apart. Neighbouring controls need at least 3px.

Done when The two controls have room between them, focus ring included.

minor duplicate-entry

Two ways to do one thing

Three controls open the same Page settings panel: the page-name gear, the tool-row gear and the Project menu.

Done when One entry point, or the others recorded as deliberate.

major copy-lint

Code names in the copy

“On primary on primary” repeats itself.

Done when A label that reads naturally, such as “Text on primary”.

With your agent

Built for the loop your agent already runs.

  1. 1

    Check. After a UI change, the agent runs idiom check <flow> and gets every finding in fix order, with a crop of each.

  2. 2

    Fix. It fixes the blocking ones and runs the check again until it is clean. Findings it disagrees with go to you, never quietly away.

  3. 3

    Gate. In CI or autobuild, idiom check <flow> --baseline <run> --fail-on major fails only on new problems.

Works with Claude Code, Codex and autobuild. Your decisions are stored in the repo, so the same finding is not raised twice.
