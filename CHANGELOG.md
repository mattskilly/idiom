# Changelog

User-visible changes to Idiom are recorded here, newest first.

## [Unreleased]

## [v0.16.1] - 2026-10-30

Idiom's MCP tools now work in Codex.

- **Codex gets its MCP server from `codex mcp add`.** Codex starts a plugin's MCP servers inside the installed plugin directory and tells them nothing about your project, so with the 0.16.0 Codex plugin every project tool failed with "no .idiom/project.json found". The Codex plugin now supplies only the Idiom skill, and one more line registers the server, which Codex starts in each thread's project directory: `codex mcp add idiom -- npx -y --package=https://github.com/mattskilly/idiom/releases/download/v0.16.1/mattskilly-idiom-0.16.1.tgz idiom mcp`. To update, rerun it with the new release. Codex users on 0.16.0 should run `codex plugin marketplace upgrade idiom`, `codex plugin add idiom@idiom` and then that line. Claude Code is unchanged.
- **The server never treats its own plugin directory as your project.** If a host starts it there, it uses the client's MCP root that contains `.idiom/project.json` when the client offers roots, and otherwise returns an error naming the fix, without reading or writing the plugin directory. An explicit `--project` and any ordinary working directory behave as before.

## [v0.16.0] - 2026-10-30

Idiom installs and updates as a Claude Code or Codex plugin, the new `idiom upgrade` brings a project's Idiom skills up to date without losing your edits, the optional critique can run on Codex, and a round of capture fixes makes reviews more accurate and private.

- **Repository marketplace installation for Claude Code and Codex.** Install Idiom by name with its MCP tools and existing skill; Claude Code keeps its UI-edit reminders. Refresh the marketplace and update the plugin to move releases. Both MCP launchers select the exact versioned GitHub release tarball, and release checks reject mismatched package, plugin, catalog and launcher versions. Local `--plugin-dir` loading remains available for development.
- **Update project skills without losing customization.** `idiom init` records tracked upstream bytes and per-file versions. New `idiom upgrade` adopts old released templates offline, merges independent edits, and validates tool-free model proposals for overlaps using review’s configured provider. Conflicts preserve the live file and its baseline while other files advance, and return nonzero. `--no-agent`, `--dry-run` and `--json` support manual and scripted workflows; rollback uses the same merge rules. See [Update and roll back](https://idiom.build/docs/update-and-roll-back).
- **Findings are ranked severity first.** Every blocker comes before every major, and every major before every minor; within each tier, findings are ordered by how noticeable the problem is and how prominent the element is, as before. Reports, `idiom check`, `idiom quick`, MCP and emitted tickets use the same order. Finding sets, scores and severity gates are unchanged.
- **Probe clicks see real scrollbars.** During interaction probes and replays Idiom now shows the page's real scrollbar, so it can measure a modal or scroll lock that removes it without compensation. Screenshots still hide scrollbars, so baselines are unchanged. Scrollbar-shift findings stay withheld until they pass the field precision gate; the measurements are recorded in timelines. Probes take about 4% longer.
- **Current model by default.** New projects set the optional critique model to `claude-sonnet-5-5` instead of `claude-sonnet-4-5`. Existing projects keep whatever `model.model` they have.
- **Critique on Codex, with a fallback.** Set `model.provider` to `codex` to run the optional critique through the authenticated Codex CLI, read-only and with no Anthropic credential. Any provider can name a `model.fallback` on a different provider; it is used only when the primary fails, and the report and a `Warning:` line say so. Review, sweep and page review honor the fallback; `idiom explore` does not and stays on Claude.
- **`token-drift` sees colours authored in `@import`-ed stylesheets.** Capture now follows readable CSS imports, including nested ones, when recording which properties a page authors. An import whose media or `supports()` condition does not match the captured viewport and colour scheme is ignored, the same way `@media` and `@supports` blocks are. Cross-origin imports are still skipped. Previously, off-token values declared in an imported sheet were silently exempted.
- **Capture follows `server.readyUrl`'s host.** Port-collision, port-monitoring and teardown checks use the host from `readyUrl`, so projects served on `http://[::1]:<port>` no longer miss a port conflict or report a server as stopped while it is still running.
- **`idiom capture --out` resolves from where you ran it.** A relative `--out` is resolved from the invoking directory, even when `--project` selects another directory. The default `.idiom/reports/<timestamp>/` still belongs to the selected project.
- **An interrupted capture no longer marks the source dirty.** Staging directories left behind by a killed capture into an explicit `--out` inside the repository are ignored when recording whether the working tree was clean.
- **Setup-derived route values stay out of saved text.** When a setup step produces a navigation URL, its path segments are now redacted from saved DOM, console and accessibility text too, including JSON-, HTML- and selector-escaped forms, so a framework that serializes route parameters cannot leak them. Redacted values use one placeholder form, `{setup-stdout:id}`, in URLs and paths alike.
- **Unresolved colour tokens stop the capture.** When a stylesheet declares colour tokens but none of them resolves to a rendered colour, capture fails with a message naming those tokens, instead of continuing with an empty allow-list that would report every colour as drift.
- **Responsive coverage says "not applicable" off the narrowest width.** `responsive-break` only evaluates the minimum captured width; report coverage now shows it as not applicable at other widths rather than as a check that ran. `target-size` runs at every width and still shows as ran, and the report note no longer says otherwise.
- **Faster capture on large stylesheets.** Recording which properties a page authors now indexes rules by their rightmost selector, the way browsers do, instead of testing every element against every rule. Results are unchanged.
- **Plugin installs show one Idiom skill.** Claude Code previously listed two `idiom` skills. Both plugins now load the same portable skill that `npx skills add` installs, so Claude Code can invoke it automatically instead of only through `/idiom`.

## [v0.15.0] - 2026-10-28

The GitHub Action's PR comment now sorts new findings into what blocks the merge, what to fix and what to consider, a portable Agent Skill and MCP registry manifest make Idiom easier for agents to adopt, and loading-ticker detection no longer depends on machine speed. A hosted review for idiom.build ships in the code but stays switched off.

- **PR reviews show what blocks, what to fix, and what to consider.** The managed Action comment groups new findings into Blocks merge, Should fix and Opportunities, expands three per tier with Problem/Fix/Done when, and collapses the rest. It links evidence filenames and the authenticated artifact download; the downloaded `index.html` contains actual crops, timeline contact sheets and full before/after images. Fix pushes reproduce the previous head and show resolved PR regressions with commit labels while the merge-base gate remains intact. Missing historical evidence is explicit; full resolution details need the matching npm CLI with summary fingerprints. Comments stay within 55,000 UTF-8 bytes, with overflow in the complete HTML report. Read-only forks retain artifacts, job summaries and warnings.

- **Hosted design review for idiom.build, shipped disabled.** Not available yet. When enabled, anyone can paste a public URL on idiom.build, optionally add a PNG/JPEG/WebP design or a reference site, and get an unlisted report. The report shows Top issues with crops, filmstrips, design drift, coverage ("what was not checked") and the install and MCP call to action. It uses the same engine as `idiom quick`: measured checks and the strict read-only probe, with no model critique. Each run executes in a fresh, nonpersistent Vercel Sandbox with no credentials, behind a public-only firewall. A guard re-validates DNS for every navigation, request and redirect, and the worker proxy dials only the checked address, so DNS rebinding cannot reach private, loopback, link-local or internal ranges. Limits: no account, BotID, three runs per IP per UTC day, 90 seconds, at most three pages per run, and a monthly spend cap (`IDIOM_HOSTED_MONTHLY_CAP_USD`) enforced atomically before any sandbox starts. Reports are `noindex` and access ends exactly seven days after creation; a daily sweep then deletes the stored files. The creator gets a delete button. The feature stays off unless `IDIOM_HOSTED_REVIEW=on`. Default site builds contain no form or client script. The cost model, ten measured local runs and the activation checklist are in `docs/hosted-review.md`. CLI capture and `idiom quick` behaviour are unchanged, and the hosted review's Vercel SDKs are development dependencies, so the npm CLI install does not include them.

- **Loading-ticker detection no longer depends on machine speed.** `loading-state-missing` tracks each changing part of the page on its own, so a response that lands right after a spinner's rotation no longer hides the spinner's rhythm. Capture also waits, within the existing hold, for the third rotation it needs to tell a self-animating ticker from feedback. The same page gives the same finding on fast and slow machines.

- **Prepared for agent discovery.** An official-schema MCP registry manifest catalogs every registered tool, and a portable Agent Skill is generated from the existing plugin/project template with explicit UI review and completion policy. Two field-guide-linked tutorials cover Claude Code design QA and testing loading, empty and error states. [Distribution instructions](docs/distribution.md) hand registry publication and public skill listing to the maintainer; no external listing is claimed.

## [v0.14.0] - 2026-10-28

Every finding now says how Idiom knows it (measured, observed or judged) and how a fix will be verified, `idiom coverage --states` shows exactly which states, viewports, schemes and replays were reviewed, and the feel checks raise fewer false alarms.

- **Findings explain their basis and how to verify a fix.** Reports, terminal summaries, JSON and MCP distinguish measured rule results, observed actions/probes and judged model suggestions, including recorded measurements, timing and stated confidence. Deterministic findings now carry executable acceptance contracts; verify reports each as passed, failed or not-recheckable with a reason, using the original target/action and unchanged settings. Older findings and ticket sidecars retain their fingerprint or visual verification behavior. Severity gates count measured and observed findings by default; `--fail-on-judged` includes judged suggestions. Configured published budgets and advisory behavior are unchanged.
- **See which states were actually reviewed.** `idiom coverage --states` shows, for each flow's latest capture and each state, which dimensions were observed: every viewport, light and dark, reduced motion on and off, the fast capture plus the slow-network and failure replays, whether the probe reached the controls and the focus sweep ran, and the `empty` / `one` / `many` / `error` data states. Each missing dimension names the exact config or flow change that covers it. Dimensions that cannot apply (no requests to replay, no controls, no data states declared, the probe on Electron) are not applicable and never count. `--json` returns the same data, and MCP `idiom_coverage` returns it as `states` (`states:true` for state coverage alone). Flow review reports (Markdown, HTML, JSON) and `idiom check` add one `State coverage:` line, worded as coverage of what was reviewed, not a measure of quality. States can label their data condition with the new optional `"data"` field, and `run.json` now records the capture's reduced-motion mode; runs captured before this release report reduced motion as missing until recaptured.
- **Timeline rules, hardened from what the v0.12 build found.** `interaction-shift` now reports a modal or other scroll lock that removes or restores the page scrollbar without `scrollbar-gutter: stable` or padding compensation, as one finding on `html` per action with the scrollbar fix. This requires a measured layout scrollbar; headless captures have no scrollbar and cannot see this cause. Content moved by a measured scrollbar change is no longer blamed on a dialog inserted beside it. `loading-state-missing` no longer counts a rotating carousel, ticker, marquee or autoplaying banner as loading feedback, or as a change after the response: such subtrees are recognised by ARIA, attributes and class names, or by changing on a regular period of their own. A web step that submits by a full-page navigation now gets one short "main-frame document navigation" coverage note instead of a long repeated reason. Each web step's slow and failure replays now run once per flow and are shared with every state reached through it, with identical findings. Beacons, requests to well-known analytics endpoints and `keepalive` fetches nothing waits on no longer stretch a probe click's late-content window. The pending heuristics the probe, loading and failure watchers share are now one in-page library. Probe summaries count reused replays (`reused`), and state coverage treats them as observed.
- **Fewer false alarms from the feel checks.** `interaction-shift` now requires the attributed change to match the direction and size of the jump, so it no longer blames a disappearing label for content moving down, or a one-pixel resize for a fifteen-pixel displacement; inserted and removed content keeps a spacing allowance for gap and margin layouts. It no longer reports the action's own collapse or dismissal (a sidebar the clicked panel closes up behind, or a panel the action hides). Content that was removed and re-rendered, or results replaced in one batch by a filter, is treated as new content rather than content pushed by a source; a placeholder swapped for results in its own slot still reports what it pushes. `motion-snap` no longer treats text written into an existing, unpainted element (such as a form's status line) as a snap; inserted elements and painted boxes such as toasts still count.
- **Two missed defects are now caught.** Text clipped by its own box is reported even inside a carousel, which no longer exempts clipping it does not cause, and an invisible status change no longer counts as loading feedback. Visible reveals and disappearance still count. Ranking is unchanged.

## [v0.13.0] - 2026-10-28

Idiom now checks what happens when a request fails, reviews only the states your change touches, and turns a repeated off-scale value into one design-system question instead of dozens of findings.

- **Failures are checked.** Two new major checks, on by default, replay actions that send a fetch or XHR request with a locally injected failure (HTTP 500 by default, or a network error). `error-state-missing` reports an action that silently returns to rest when its request fails, with no alert, status message or visible result. `retry-blocked` reports an action that cannot be retried after a failure: its trigger stays disabled, busy or hidden, a spinner never clears, or the region it acted on lost its content. Failed requests are answered locally and never reach your server. Each finding links the failure replay's timeline and filmstrip. Configure them with `checks.failure` (`mode`, `status`, `feedbackWithinMs`). Earlier captures need recapturing.
- **Check only what changed.** `idiom check [flow] --changed [base]` and MCP `idiom_check` with `changed:true` or a base string capture only states affected by Git changes, including uncommitted and untracked edits. Route ownership and transitive relative/tsconfig-alias imports explain selection; global or unattributable files select all candidate states, while a module-local unresolved import or a `urlFrom` state only adds the states it could affect. Output discloses skipped states, existing baselines remain comparable without marking omitted findings fixed, and partial runs never initialize a baseline. Claude Code reminders suggest changed checking.
- **Repeated drift becomes a question.** When one off-scale value keeps appearing in the same context (for example, 17px padding on every table-row control against 16px and 24px steps), `scale-conformance` now asks one design-system question instead of filing every occurrence as a finding. The context is the nearest landmark, the component and the viewport. A value qualifies at `checks.scales.suggestAfter` occurrences (default 5) across two states or three elements. Reports and `idiom check` list these under "Design system questions", with the count, the nearest declared steps, a suggested token name and crops of three examples. Answer with `idiom ruling --decision ruling-N --add-step [--token <name>]` to record the step in DESIGN.md, which closes those findings in that context, or with `--drift` to keep reporting the value as one grouped finding. MCP `idiom_decide` accepts `add-step` and `drift` for `ruling-N` ids. An unanswered question is asked again next run, and Idiom never changes the scale or DESIGN.md without a recorded answer. Small or scattered repeats, undeclared outliers and `idiom quick` are reported as before. A malformed ruling block in DESIGN.md now fails `idiom check` as it already failed `idiom ruling`.
- **Seeded-defect benchmark.** `scripts/mutation-bench.mjs` seeds fourteen kinds of defect into clean fixture pages with deterministic DOM and CSS edits, checks that Idiom reports each one on the edited element, and reports misses and where each catch ranks. A fixed twelve-case selection runs in the test suite, so a change that loses a previously caught case fails the tests. Detection rules are unchanged in this release.

## [v0.12.0] - 2026-10-27

Idiom now reviews what using the app feels like, not only how each screen looks. It records what happens during every page load, click and web step, and major checks built on those recordings catch content that jumps when you act, actions that show nothing while they wait or can be submitted twice, and changes that snap into place.

- **Idiom records what happens between states.** Capture now records what the user experiences during every action: the page load, each web step and each interaction-probe click. Each tuple gets a `timelines.json` with the layout shifts (including those right after input, which Core Web Vitals ignores), how far each element moved and when, scroll-compensated so scrolling a control into view does not count, content inserted or removed, animations and transitions, View Transitions, and the requests each action started with their timing. Recording itself only observes: it adds no clicks, replays or waiting, and follows the probe's read-only network policy (loading-state checks and `motion` add their replay windows, above). Size is capped per action and truncation is reported, never silent. Findings can reference an action timeline, which `idiom check --json` and `idiom_issue` return. Motion, loading-state and layout-stability checks use these timelines; runs captured before this release load unchanged and report timelines as unavailable until recaptured.
- **Content that moves when you act is caught.** New major rule `interaction-shift`, on by default: after a probe click or web step, content outside what the action changes that jumps at least 4px without animation, because something was inserted, removed or resized, is reported with the cause, the distance, the time after input and the moved elements. Content arriving more than 500ms after input (async data, lazy images, banners) is reported even inside the action's own region. Scrolling, sorting and filtering inside a list, animated movement, overlays, off-screen movement and a panel the click itself opens, closes or dismisses are not shifts. Each fix is generated from the measured size: reserve the height or aspect ratio, render a skeleton, or overlay instead of pushing. Configure with `checks.interactionShift` (`enabled`, `minDistance`); recapture older runs.
- `layout-shift` is now **major**, and with a load timeline it names the late content behind the largest shift (for example, a promo inserted 320ms into load) and how much space to reserve.
- A probe click whose own request is still in flight when its effect window ends now waits for the response, up to 2 s from the click, so late content is part of the click's timeline. Clicks that start no request are timed as before.
- **Missing loading states are found without declaring anything.** Locally every response is instant, so a click that shows nothing while it waits never appears in a capture. The interaction probe now replays each click and web step that sent fetch, XHR or document requests with those responses held for `checks.loading.delayMs` (default 1500ms), as a slow network would, and watches what the user sees. Two new major rules, on by default: `idiom:loading-state-missing` reports an action that shows no spinner, progress bar, `aria-busy`, skeleton, status text, disabled trigger or other visible change within `checks.progressWithinMs` and changes only after the response, naming the trigger, the requests and the silent time; a client-side route change that leaves the main content empty or unchanged is judged the same way, and a highlighted nav link or route announcer does not count as feedback. `idiom:double-submit` reports a trigger left enabled while its POST, PUT, PATCH or DELETE is pending, where activating it again issues a duplicate. The replay never sends a request the probe would not: held requests pass the same read-only guard, and the duplicate is aborted before it leaves the browser. Each finding carries a fix built from the evidence (a pending state on the trigger, disabling it while pending, a skeleton sized to the final content) and links its `slow-replay` action timeline. Full-page navigations, beacons nothing waits on, and steps marked `longRunning` (still judged by `progress-affordance`) are not reported. Each replay costs about one restore plus the hold and counts against the probe budget, at most six per state. Runs captured before this release report both rules unavailable until recaptured.
- **Changes that snap are caught.** `motion` now reports content that snaps after an action, not only overlays: tab and segmented-control swaps, inline expand/collapse, list items added or removed, toasts and status messages, and client-side route changes (`idiom:motion-snap`). A snap is a visible change of at least 24px (`checks.motion.minExtentPx`) with no animation, transition or View Transition; text-only changes, focus rings and changes to the clicked control are ignored. One finding per surface and kind of change lists every action that produced it, and its fix names a concrete transition from your motion durations and the property to animate. Snaps are a "feel" rule and are now **major**, including overlay snaps (`idiom:motion-no-transition`); duration findings stay minor. Under reduced motion an instant change is correct, so in the default reduced-motion capture the probe replays each suspected snap once under normal motion to confirm it, at most one replay per surface and kind and six per state. Action timelines record the visible changes, the reduced-motion preference and the starting path; recapture older runs to get content snaps (they keep the overlay behaviour).
- **See what happens between states.** Web capture retains bounded screenshot filmstrips for temporal findings and explicit action requests, at configurable offsets plus settle. Findings receive labelled PNG contact sheets with moving red outlines; MCP returns them before static crops, JSON and Markdown include their paths, and HTML embeds them. Verification preserves the historical sheet and a matching after action even when the defect is fixed. Missing, partial and legacy evidence stay explicit. Configure `capture.filmstrips`; Electron capture is unchanged.
- **Quick review interacts with the page.** `idiom quick` and MCP `idiom_quick` now run the interaction probe once per page at the first selected viewport in light, so dead-control, duplicate-entry, motion and the other probe-based rules work without configuration. Each page gets 45 s for the focus sweep and clicks together, and at most 40 controls. 45 s covers about 20–40 controls on a typical page at the 1–2.6 s per control measured in configured flows, and bounds the additional interaction work on slow third-party pages (teardown can add a short tail). 40 is half the configured 80: third-party pages carry large shared navigation, and the probe takes a page's own controls first, so the cap cuts the least informative tail. `--probe-budget <ms>` (MCP `probeBudgetMs`) changes the time; `--no-probe` (MCP `probe:false`) restores the static review. The probe is strict on pages you may not own. Only GET, HEAD and OPTIONS requests leave the browser. Cross-origin navigation, form submission, downloads, new windows and permission prompts are blocked, service workers are off, and destructive-looking controls are skipped. Reports say what was clicked, skipped, not reached and blocked; the probe artifact records it as `probe.safety`. Configured flows probe exactly as before.
- **MCP reaches parity with the CLI.** Seven new tools let an agent drive Idiom without a shell: `idiom_init`, `idiom_design_add`, `idiom_choose` (choose between disagreeing design references), `idiom_tickets` (clustered triage proposals), `idiom_sweep`, `idiom_coverage` and `idiom_baseline` (show or record). Each runs the same code as its CLI command, stays inside the bound project root, and keeps human judgment with the human: choosing a reference needs the human's reason, preserved verbatim. Tools still take no credentials; `FIGMA_TOKEN` and model keys come from the MCP server's environment. [docs/mcp.md](docs/mcp.md) now has a CLI parity table listing every command as an MCP tool or CLI-only with the reason.
- **Claude Code reminds agents to check UI changes.** The bundled plugin names edited UI files and all configured flows/states after an edit, then reminds once before stopping if the UI has changed since a successful live CLI or MCP check. Hooks never capture. Configure `agent.uiGlobs` or opt out with `agent.hooks: false` in `.idiom/project.json`; see [docs/mcp.md](docs/mcp.md).
- **Whole-product polish after autonomous builds.** `idiom sweep --all` captures every validated flow and groups shared causes into a cleanup set ranked by salience × prominence. `--max-tickets` defaults to 10 new triage proposals after finding-id deduplication; uncapped findings, omitted counts and honest flow/probe/check/model coverage remain in Markdown, HTML and JSON polish reports. Tickets retain all source coordinates, measurements and crops, bounded repair instructions and exact per-flow/tuple verification sidecars. `--deterministic-only` runs without model credentials. MCP `idiom_sweep` supports the same selectors, budgets and reports. Operators review and groom emitted proposals manually.

## [v0.11.0] - 2026-10-27

Idiom now judges only what people can see, and its rules are much stricter about what counts as a problem on sites it has never seen.

- **Only what people can see is judged.** Geometry, copy and consistency heuristics ignore wholly unpainted elements, with per-rule skip counts in JSON, Markdown and HTML coverage. Existing captures retain their previous review behavior. Capture waits naturally for finite entrance animations and transitions within `capture.animationSettleMs` (default 1500ms), and preserves unresolved animation state in evidence screenshots.
- **Generated flows contain only real pages.** `idiom init --flows` keeps a discovered route only when both the response and the settled document are HTML, so images, feeds and JSON no longer become states or receive document-structure findings such as a missing `h1`. Underscore-prefixed (private) directories and non-page files are skipped, Astro projects admit only page formats, and routes that return 404 become TODO notes instead of states. Hand-written flows are unchanged.
- **Crops show their element on very tall pages.** Crops on very tall pages and on pages that overflow the viewport horizontally now show their element. Full-page captures taller than the browser's texture limit are taken in tiles and stitched, and `metadata.json` records which screenshot strategy was used. Crops also follow content that moved between observing the page and taking the screenshot.

Rules tightened so their findings hold up on unfamiliar sites:

- `idiom:orphan-word` judges only words that are visibly painted: words hidden by a reveal mask or clipped away by an ancestor no longer form a line, and a stranded word that leaves no ink in the captured screenshot is skipped and counted in coverage. Inline `role="button"` sentences in running copy are no longer treated as labels. Its crop now shows the measured text instead of whatever the selector matched, and crops of full-page captures that overflow horizontally are no longer offset. Recapture to get the new evidence; older captures keep their previous behaviour.
- `idiom:mixed-locale-spelling` no longer reports a link that names a titled page (matching title metadata, `<cite>` ancestry, or a capitalised name with a title), or a declared `properNouns` span such as "Centre Pompidou". Buttons, single-word and untitled links in the minority locale still report.
- Input groups whose controls share a 1px border (Bootstrap's `.input-group`) no longer count as overlapping controls.
- Keycap glyph groups and static product mock-ups no longer count as touching controls; captures record each element's `user-select`.
- `idiom:image-distorted` no longer reports a stretch that is under 1px on either axis after the best proportional scaling, such as a small icon a few percent out of proportion. Visibly stretched photos and logos are still reported, and existing captures are re-judged without recapture.
- Labels above underlines or below dividers are measured against their content box, avoiding off-centre reports caused by one-sided decoration.
- A chart's tooltip no longer counts as overlapping the chart it describes, and below-the-fold overlaps confirmed only by geometry are reported as minor.
- `idiom:scale-outlier` compares only peers: prevailing values are per colour scheme, and heading rules, table borders and other dividers are separate scales. Dotted or dashed underlines on inline text are no longer dividers, and radius is skipped on controls with no visible background, border or shadow (this also applies to `idiom:off-scale-radius`).
- `idiom:element-content-clipped` reports a box only when it cuts off painted text or a control. Decorative overflow (glows, bleeds, imagery), `aria-hidden` or `inert` illustrations, content a nearer scroller owns, and marquee tracks no longer report. Captures made before this release keep their previous behaviour.
- `idiom:selected-state-invisible` sees custom selection indicators (a dot or check rendered beside the label, including SVG and pseudo-elements) and reads native radio and checkbox state from the live control, so a visibly selected custom option is no longer reported.
- `idiom:sibling-select-inconsistent` compares only controls of the same family, element and role. A select is no longer compared with an icon-only menu button; same-type padding differences still report.
- `idiom:text-clipped` no longer reports a vertical overrun smaller than the font's descender space when no glyph ink is cut, or a moving marquee track whose repeated text is meant to run past its strip.
- `idiom:dead-link-text` ignores action-like copy inside non-interactive product illustrations (decorative frames with no interactive descendants).
- `idiom:mixed-label-casing` ignores hidden labels and capitalised multi-word links that name a real page (matching title metadata or a `<cite>` ancestor).
- `idiom:line-too-long` measures characters on each rendered line instead of estimating from the element's width, and records the line count and widest line in pixels. Single-line text in a wide column is no longer reported by column capacity.
- `idiom:minimum-target-size` applies the WCAG 2.5.8 spacing exception (an undersized target with enough clear space around it passes) and credits the clickable area a label adds to a native checkbox or radio.

## [v0.10.0] - 2026-10-26

Idiom now works inside your coding agent and compares what you built against what you designed.

- **Use Idiom from your coding agent.** `idiom mcp` runs a local MCP server over stdio with eight tools: `idiom_quick`, `idiom_check`, `idiom_issue`, `idiom_fix_plan`, `idiom_verify`, `idiom_context`, `idiom_flows` and `idiom_decide`. It needs no HTTP service or model credentials. Claude Code: `claude mcp add idiom -- npx -y @mattskilly/idiom mcp`. Setup for Codex, Cursor and Claude Desktop is in [docs/mcp.md](docs/mcp.md). The package also bundles a Claude Code plugin manifest.
- **Top issues are ranked by salience × prominence.** Salience is how noticeable the kind of problem is. Prominence is how much of the viewport the element covers, whether it is in view, whether it is a primary action or in the primary region, and how many states and places it affects. Severity breaks ties. `--top N` limits what is shown; `--json` always has the full ranked list. Detection, fingerprints, decisions, baselines and `--fail-on` are unchanged. See [docs/ranking.md](docs/ranking.md).
- **One root cause, one issue.** Symptoms that share a source (a design token or CSS custom property, a component, an authored style rule or a page region) collapse into one issue. It states the cause, the evidence and its symptoms with counts, for example an unresolved `--r-md` producing radius, spacing and shadow drift on nine controls. `scale-conformance` now also measures authored `box-shadow` on controls.

- Added `idiom learn --state <state> "<what's wrong>"`, coaching from misses: a human observation becomes a `checks.components` size, a state size invariant, a `checks.copy.glossary` term or a `checks.mirrored` pair (subjects are resolved to selectors from the state's stored capture, or `--selector`), and anything else a design-law ruling through the ruling machinery (`--ruling`, `--wording`). Each learning appends a provenance line, with the capture it was seen on and an optional `--screenshot`, to `.idiom/learned.jsonl` (commit it). Nothing is written until the exact diff is confirmed (`--yes` skips the prompt).
