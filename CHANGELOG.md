# Changelog

User-visible changes to Idiom are recorded here, newest first.

## [Unreleased]

## [v0.9.0] - 2026-10-25

Idiom stands on its own as a design reviewer and QA agent. It learns your design system from code, generates flows from your routes, catches the benchmark with zero configuration, leads with the top issues, guards regressions by default (with a GitHub Action), and runs the repair loop with `idiom fix`. The interaction probe can no longer hang a capture, and a start command that pins its port now fails fast with the fix. Benchmark: 7/7 before, none after, with no `checks` config.

- Added `idiom fix <flow>`: check, repair and verify in a loop. Idiom hands the top findings (`--top`, default 5) to your coding agent (Claude Code by default, `--agent codex`) with selectors, measurements, design rules and crops, then recaptures the whole flow. A round counts as progress only when the existing verify path proves the targeted findings fixed; any newly introduced deterministic occurrence, at any severity, fails the round and stops. `--max-rounds` (default 3) bounds the loop, `--dry-run` prints the prompt without running an agent, and the command exits 0 only when no eligible work remains. Uses your agent CLI's own authentication; there is no provider fallback. See [docs/commands.md](docs/commands.md#fix).
- Added `idiom system --learn`: proposes `design.tokens` and `checks.scales` from Tailwind v3 config, Tailwind v4 `@theme`, CSS custom properties (`:root` and `[data-theme]`) and DTCG token JSON, and applies the diff only after confirmation (`--yes` to apply non-interactively). Existing human values are never replaced, inferred purposes are labelled, Tailwind defaults are excluded, and ambiguous or conflicting sources are disclosed instead of becoming rules. `checks.scales.spacing` now also accepts base-step entries such as `{ "multipleOf": 4 }`.
- Captures can no longer hang. The interaction probe has per-control (`checks.probe.controlTimeoutMs`, default 5000) and per-state (`checks.probe.stateTimeoutMs`, default 60000) budgets, and the whole capture has `capture.maxMinutes` (default 30). Expired work is recorded as timed out with its selector and elapsed time, and the probe moves on. Native dialogs, print, file choosers, downloads and popups are suppressed during the probe, probe progress is printed to stderr, and timings list the five slowest controls. Timed-out controls are never reported as dead or duplicate.

- The README now explains Idiom in one screen; the command reference moved to `docs/commands.md` and configuration to `docs/configuration.md`.
- `check` now automatically accepts its first clean HEAD capture as a compact baseline, then reports new/fixed/pre-existing occurrences and gates only new findings. Commit the record; `baseline accept [flow]` explicitly advances it. `--all` reports and gates every open finding. Explicit baseline selectors remain strict; `--baseline-file` and baseline `--out` support isolated CI records.
- Added the repository GitHub Action: merge-base/head captures, one updated PR comment, new-finding crops and before/after composites in a GitHub artifact with an HTML index, followed by the severity gate. See the copy-ready workflow in [docs/configuration.md](docs/configuration.md#github-action); publish the snapshot and compatible npm CLI together.

- The full `check --all` view leads with Top issues (default five, `--top <n>`), ranked by severity, distinct places and primary action. Similar sibling selectors collapse into one issue with a count and example; remaining issues are counted per category. `--all` lists every issue and sibling group. `--all --json` keeps every open finding and group and adds the complete ranked `issues` array; decisions and reports retain their identities.
- Default target-size thresholds now follow input class at every viewport: desktop-first flows use 24px for fine pointers; mobile below 768px and touch keep 44px. `checks.targetSize` still overrides. Existing decisions match because fingerprints are unchanged. Re-record baselines after adopting the new defaults: projects without the block retain their configuration hash, but newly checked desktop coordinates can introduce new findings.

Idiom now catches the design-partner benchmark with zero configuration (file-163). With v0.8.0 and the project's own config, about three of the seven human-found defects were reported; the rest needed opt-in settings real users never turn on. Four defaults change, each with an opt-out. Benchmark: 7/7 before, 0 after, with **no** `checks` config.

- **The interaction probe is on by default for web flows.** It runs once per state at the first selected viewport (light preferred), within the per-control and per-state budgets added in #84, and it clicks enabled controls in a disposable page (destructive-looking names, `checks.probe.skip` and dialogs/downloads are still suppressed). Dead buttons and duplicate entry points are now found without configuration. Turn it off with `"checks": { "probe": { "enabled": false } }`, or per state with `"probe": false`. Toggle-combination states stay unprobed unless their base sets `"probe": true`. Electron is unchanged (unsupported).
- **Unexplained text glyphs are reported by default.** An enabled control whose painted text is a glyph or symbol (`?`, `i`, `ⓘ`) is a minor `unexplained-control` finding when the probe sampled both hover and focus and neither showed a tooltip, even when it carries an `aria-label` or native `title`. Painted `aria-describedby` text or an observed tooltip clears it; bare icon buttons and controls without hover/focus evidence are not reported. Opt out with `checks.probe.enabled: false`, or skip specific controls with `checks.probe.skip`. The full `explanation: "visible"` mode stays opt-in.
- **Component sizes are inferred from DESIGN.md.** A size stated next to a name ("override dots … about 8px", "chips 24px high", "cards 320×200px") becomes a component-size spec; capture resolves its selector from class tokens (then `aria-label` words) containing the name, and findings cite the line ("inferred from DESIGN.md:12"). `idiom context` lists the inferred sizes and report coverage shows what each matched, or that nothing did. Explicit `checks.components` with the same name or selector wins; to stop an inference, reword the sentence or declare the component.
- **Disabled navigation-like buttons are reported by default.** `idiom:disabled-link-button` (a disabled "Help", "View terms" or "Learn more" button) no longer needs `explanation: "visible"`. It is minor, below the default `--fail-on major` gate, and has no separate switch: accept individual instances with a decision or ruling. Captures without painted-text evidence keep the old behaviour.

- `idiom init --flows` and an interactive init offer generate a `site` flow from Next.js routes, sitemaps and a bounded link crawl, using project capture axes. Dynamic-route and login setup TODOs remain explicit; web `expect.path` prevents successful captures of a redirected destination.

- A start command that pins its own port (for example `next start --port 3100` inside a package script) now fails within seconds with the fix (`"server.fixedPort": true` or `--port`) instead of timing out on the reserved free port.

## [v0.8.0] - 2026-10-24

The first public release. Idiom now installs from npm as `@mattskilly/idiom` (`npm install -g @mattskilly/idiom`); the git-tag install is retired. Completes the second round of dogfooding requests with page-gutter and word-break checks, gallery media-fill and collection-action checks, and an advisory design-intent review for patterns and templates (#65, #66, #69, #73 and #74). Benchmark unchanged: 7/7 before, none after.

- Advisory design-intent review for patterns and templates (dogfooding request #69). On the starting checkout, neither planted shape was caught by any rule: a section heading touching its card row and a marquee of placeholder logos that read as broken thumbnails both produced only the `heading-structure` hit. A web flow's new optional `content.patterns` declares each pattern's `id`, `intent`, a `path` (captured as a generated `pattern-<id>` state) or an existing `state`, and an optional design `reference`, managed or file, with exact-name pairing. The model reviews one pattern per request, using the page-review section list and validation, the measured geometry and the reference, and reports only spacing, hierarchy and coherence problems, each with a section, an `aspect`, a fix and a crop. Results go to `advisory.json` and a separate report section, never to `findings.json`, groups, tickets or the gate. `review` runs the pass when `content` is declared. `check --advisory` opts in and never changes the exit code. Existing flows, prompts and output are unchanged.
- Added gallery media-fill and collection-actions checks (dogfooding requests #73 and #74). Both gaps were reproduced on the starting checkout and neither was already covered: no check reported template thumbnails with a white band about 40% deep over a cropped, scaled preview, letterboxed card images, or dashboard cards and project rows with no way to delete or rename them. `media-fill` (on by default; `checks.mediaFill` sets `bandThreshold`, `tolerance` and `ignore`, and `auto: false` turns it off) samples each gallery frame's edges from the capture screenshot and reports, once per gallery of three or more repeated cards, solid backdrop-coloured edge bands, letterboxing or blank frames; the threshold applies at check time, so stored evidence re-judges offline. `collection-actions` (opt-in through `checks.collections`) is a minor "Heuristic:" finding when open, rename or delete is not reachable from a declared collection's items, their menu or their context menu; with `checks.probe` on, a read-only pass opens each item's menu and context menu and records menu items without clicking them, so destructive entries are seen but never invoked. Finding severities have no info level, so the advisory check uses `minor`, below the default `--fail-on major` gate. Older captures request recapture for both checks.
- Added optional page gutter and word-break checks for dogfooding requests #65 and #66; both gaps reproduced on current code before implementation. `checks.bandEdges` reports inset navigation or section content against dominant page gutters per viewport (default tolerance 8px), exempting full-bleed media. `checks.wordBreak` detects unhyphenated heading/button word splits even when scroll dimensions fit. Both are disabled unless configured, preserve offline geometry evidence, and require recapture after enabling; uncertain measurements are disclosed in coverage.

## [v0.7.0] - 2026-10-24

Faster, steadier capture, and checks for what an AI-built app shell gets wrong. Every capture gets its own port, states can be reached by interaction from another state, checks can be scoped and production builds reused, and install by tag is verified. New checks cover app-shell visibility, retired terms and jargon, touch reachability and liveness, and compound controls (dogfooding requests #46–#50, #57, #64, #67, #68, #70 and #72). Benchmark unchanged: 7/7 before, none after.

- Compound controls and sibling chrome (dogfooding requests #70 and #72). Neither defect was reported on the starting checkout: a Size field showing a "px" unit select beside a "px" suffix sitting on the input's right border, and a left panel whose collapse toggle appears in every panel but the AI panel. Opt-in `checks.compoundControls` (`tokenMax`, `minInset`) adds `compound-control`, which reports a short token shown twice across a select and an adjacent input adornment, and adornments that cross the input border, crowd its inner edge or cover its content box. Opt-in `checks.siblingChrome.regions` adds `sibling-chrome`, which compares named controls (role and accessible name) inside those regions across states that declare `siblingGroup` (run-wide) or `group` (within a flow), and reports a control missing from one sibling. Captures now record select-like display values and the state's sibling declaration; recapture to use either check. Groups are never inferred. Existing configuration and output are unchanged.

- Added opt-in touch reachability and liveness checks (dogfooding requests #67 and #68). Touch emulation (per-viewport `touch: true`: coarse pointer, no hover, touch points) already existed and needed no change; both detection gaps were reproduced on the starting checkout. `checks.touchReachability` reports enabled controls hidden at rest on a touch tuple that CSS hover on their painted owner reveals, with no painted tap-focusable CSS alternative, using Chromium forced pseudo states after saved evidence and before the probe. `checks.liveness` samples declared selectors or timer-like text twice ~1.5s apart and reports unchanged or all-zero values. Evidence is stored for offline review; older captures request recapture.
- Retired terminology, jargon and locale spelling (dogfooding request #48): opt-in `checks.copy.retired` and `jargon` require concrete replacements and report each offending term with its element crop. An optional `.idiom/glossary.json` merges additively with project policy, with project terms and locale taking precedence. Added explicit Canadian and Australian spelling policies, including Canadian `Colours` alongside `Organize`, and concrete spelling replacements for all four locales. Legacy glossary matching already caught phrases inside longer labels case-insensitively, and existing report crops already worked; both remain regression-tested. Captures now retain `translate` so the existing copy exclusion applies to `translate="no"` text.

- Added opt-in shell and selection visibility checks (dogfooding requests #46 and #47). All three gaps were reproduced on the starting checkout: a visually hidden absolute span extending an app shell, a selected footer outside the visible canvas, and intersecting floating selection overlays. Flow `shell` checks exact scroll/client heights and viewport bounds; web `expectVisible` steps assert viewport/scrollport visibility without scrolling and survive document navigation during polling; `checks.shellVisibility.floatingOverlays` compares declared peers. Capture evidence supports offline review; older captures request recapture.

- Build provenance and tag-install recovery (dogfooding request #49): `idiom --version` and `-V` now print the package version plus the embedded short source commit, while capture/baseline artifact versions remain bare semantic versions. Tag installs already succeeded on Bun 1.4.4; provenance and recovery instructions were missing. The [installation procedure](README.md#try-idiom-in-two-minutes) now records that minimum verified installer, the quoted tag path, and a full-commit fallback peeled from the intended tag. The [release gates](docs/releases.md) require isolated, cleared caches for both install forms and distinguish build-source from installation commits. Published `v0.6.0` retains its historical bare version output.

- Faster scoped checks (dogfooding request #64): `capture` and `check` accept `--states`, `--viewports` and `--schemes`; recorded scope discloses skipped coverage and keeps partial runs out of unscoped `--latest`. Interaction probes prefer light at the first selected viewport, with a dark-only fallback and optional `checks.probe.everywhere`. Opt-in `server.production.reuseBuild` reuses validated clean-commit output across flows while repeating setup and server startup. Every run records and prints phase timings; replay keeps capture timings immutable and measures current checks separately. Internal exact-coordinate filtering, once-per-state probing, production port rebasing, output restoration and build provenance were already implemented and remain regression-tested.

- Each web capture now serves on its own free port, preventing concurrent worktrees from colliding or capturing each other's server (dogfooding request #50). Build and start receive `PORT`; ready URLs, environment values, command port tokens and state URLs follow it. Override with `--port` or `IDIOM_PORT`, or set `server.fixedPort: true` for apps that require the configured port. An occupied ready URL is refused before startup with “port in use by another process”. Derived evidence uses the configured origin for stable console-finding identity; metadata retains the actual served origin and records `canonicalOrigin`, preserving expected-status document-load suppression. Production free-port allocation and the 127.0.0.1 conflict check were already on main; development allocation and the ready-host check are new.

- States reached from another state (dogfooding request #57): a web state may declare `from: "<stateId>"` instead of `url`/`urlFrom` to load that state (its URL and steps) and then run its own `steps`, so panels behind a click, such as a version history tab, can be captured and probed. Chains may be multi-hop; unknown ids and cycles fail validation at `states[i].from`. A failing step names the chain (`Step 1 (click) of "empty" reaching versions from empty: …`), and report coverage, `idiom coverage` and capture metadata show the chain (`versions from empty`). Also new: a `focus` web step. Already on main: loading a URL then running `click`/`fill`/`press` steps. Existing flows are unchanged; plain step failures keep the `Step N (action): …` form.

## [v0.6.0] - 2026-10-24

The tag team, and the first round of dogfooding fixes. Adds `idiom sweep`, `idiom learn`, `review --page`, group invariants and collapsed repeated findings, then quiets and sharpens the checks against a real AI-built app (dogfooding requests #51–#63 and #71). Benchmark unchanged: 7/7 before, none after.

- Quieter defaults for names, media crops and internal routes (dogfooding requests #60, #61 and #62; all three reproduced on main, none already covered). `copy-lint` no longer reports Title Case pattern names in a design partner's AI-built page builder ("Hero Centered", "CTA Centered") as sibling labels cased two ways when they are declared in the new `checks.copy.properNouns` (case-sensitive whole phrases, so a mis-cased variant is still compared) or when each item of the list or grid collection carries `data-idiom-name`; glossary hits inside named items still report. `overflow-clip` no longer reports dashboard thumbnails (scaled iframes cropped by their cards: 96×77 in 96×72, 361×289 in 361×225): a textless box whose children are all `iframe`, `img`, `video` or `canvas` elements, or wrappers holding exactly one, is crop-to-fit by design, as is any box marked `data-idiom-crop`; `clipped-text` still reports text clipped inside them. `idiom coverage` honours the new `coverage.exclude` globs in `.idiom/project.json` (a leading `/` matches the route, otherwise the source path), applied before routes are de-duplicated, says how many routes were excluded, and shows the concrete paths flows used for dynamic routes (`/p/[id] (e.g. /p/abc123)`); `--json` gains `excluded` and `examples`. Without the new config or attributes, the only changes are the media-crop exemption and the dynamic-route examples. The `data-idiom-*` attributes are read at capture, so recapture after adding them.

- `text-centering` measures only painted text and centres single-glyph labels on their ink box (dogfooding requests #59 and #71). Icon buttons whose label is visually hidden (sr-only `clip` or `clip-path` patterns) are no longer reported, and centred `+`/`−`/`×` stepper glyphs no longer read as off-centre. Genuinely off-centre glyphs and the benchmark specimen chip are still found. This corrects a measurement, so there is no new configuration and `centeringTolerance` is unchanged. Capture records a new optional `signals.labelInk`; older captures keep the previous measurement until recaptured. Neither part was fixed on main before this change.

- Fixed interaction-probe noise for already-selected options, drag handles and native pickers (dogfooding request #54). Opt in with `checks.probe.respectControlIntent: true` alongside existing probe enabling. Selected controls and drag handles now have explicit skip reasons, including nested menu items; real file choosers and native picker activation count as effects. Canceled, disabled or non-opening picker attempts (including range datalists and listbox selects) and enabled inert buttons still report as dead. The option defaults to false; recapture to collect the new evidence. Existing offline skip/effect suppression was already supported; capture classification and native picker evidence are new.

- `adjacent-gap` now compares sibling controls, not page layout (dogfooding requests #58 and #71, benchmark defect 5). Layout regions (landmarks, `nav`/`main`/`aside`/`section`/`dialog` and their roles, dialog sections, and panels holding a heading or a bordered group of controls) and non-interactive indicators no larger than 16px are never compared, so flush rails, content panels, controls bars and stacked dialog sections are no longer reported, nor are 8px dots beside unit buttons. Controls are compared with each other wherever they sit; bordered shapes only within the same direct parent (a shape wrapped in an extra unbordered `div` on one side is therefore not compared). Findings name the shared parent ("… in `#composer`") and add `parent` to their verification params; rule ids, selectors and fingerprints are unchanged. The focus ring now includes `outline-offset`, so a composer prompt whose 2px ring sits 2px out is reported as a major collision with Send rather than a minor one; captures without the recorded offset measure as before. Already on main: stepper −/+ buttons touching their number input were reported; that is now regression-tested. New optional config: `checks.adjacentGap.regions` (selectors that are flush by design, resolved at capture) and `checks.adjacentGap.indicatorMax`. The benchmark composer now models the real shape (a borderless prompt in a label inside a bordered wrapper, Send with `aria-label` and `title`); the benchmark still scores 7/7 before and none after.

- Added opt-in `checks.explanation: "visible"` (dogfooding request #55): icon/glyph controls need painted labels, visible associated descriptions, or tooltips observed independently on hover and focus. Capture and probe evidence persists for offline checks; older captures need recapturing for this mode. The same option flags disabled navigation buttons such as “Help” and “View terms” as minor placeholder-link suggestions. The benchmark now uses meaningful aria-labels plus native titles and aria-disabled buttons, retaining 7/7 before and no defects after. Visible evidence excludes off-screen, fully clipped and transparent words, stays attached to the same control across navigation/replacement, and supports safe hover/focus sampling of aria-disabled glyphs. Disabled navigation detection includes fieldset inheritance and its first-legend exception. Default behavior is unchanged.

- Component-size defaults now use the smaller of 15% and 1px per dimension (dogfooding request #56), catching 12px override dots declared at 8px. The benchmark now uses the real 12px size. Explicit tolerance objects retain their 25%/4px defaults and larger-of behavior unless `mode: "tighter"` is set; older captures retain their recorded policy. Findings already printed the applied tolerance, which is now regression-tested for both policies.

- Added per-input target-size thresholds (dogfooding request #53): optional `checks.targetSize` sets fine-pointer, touch and narrow-screen minimums per viewport, and viewport `touch: true` enables touch emulation. Findings name the applied class and minimum; without the configuration, behaviour is unchanged.

- Added `group` flow invariants and the `group-invariants` check (dogfooding request #41): declare a list selector, an item selector and an `attribute` or `text` pattern every item must share with the list's owner (the list itself, or a declared `owner`), and each list holding items from elsewhere becomes one finding naming the stray items. Capture stores raw membership values so `review --from` re-judges offline; earlier captures report the check as unavailable until recaptured.

- Collapse repeated findings (dogfooding request #52): `idiom check` lists the same element failing the same rule once, with the states, viewports and colour schemes it was seen in, its member finding IDs and one representative crop. Groups take their worst member's severity and rank by severity, then by coordinate count. `check --json` adds `groups` with every member coordinate, each review run writes `groups.json`, the Markdown and HTML reports gain a Repeated findings section, and `idiom decide --group <id>` decides every member. `check --ungrouped` restores the per-finding listing. Already on main: findings collapsed across viewports by fingerprint, but the viewport list was dropped; it is now recovered, and grouping across states and schemes is new. Finding IDs, fingerprints, decisions and `--fail-on` are unchanged.

- Fixed `duplicate-entry` misses and false positives (dogfooding requests #51 and #63; both reproduced on main). Controls are now identified by location rather than accessible name: two "Page settings" gears in different regions plus the project-menu item are one finding listing all three locations, and look-alike tools in a `role=toolbar` or `role=menubar` count as a repeated list only when 3+ share a name, so a distinct gear among Undo and Redo is an entry point (per-row actions in other repeated lists, including bare-button layer lists, stay excluded). Focus that follows another effect ("Keep current project brand" then focusing the prompt) is a side effect; a focus-only duplicate is reported only when focusing is each control's sole effect. Probe results carry optional `region` and `primary` fields; stored artifacts without them re-check as before. The benchmark's tool row is now a real toolbar, so defect 2 is guarded the way it appears in the dogfood app.

- Added `idiom review --page <url>` (dogfooding requests #31 and #16): reviews one rendered page, such as a generated landing page, without a flow. It runs every deterministic check plus the new opt-in `page-content` check: placeholder and lorem copy, a hero and final section without a button-styled CTA, missing image alt text, and, with `--brief`, statistics the brief does not contain. With `--brief` and `--direction`, the model critique reports `direction-drift`, `offer-change` and `unsupported-claim` findings. Each names its page section, cites the numbered brief or direction line (validated against the file) and gives a concrete fix. `--focus` (hierarchy, primary-action, naming, radii-heights, jargon) ranks requested areas first, and `--frame` adds reference frames. `checks.page` (`ctaSelectors`, `placeholderPatterns`, `claimsAllow`) tunes the check and turns it on for flow captures; flows without it report `page-content` as skipped. `review <flow>` is unchanged.

- Added `idiom sweep <flow>`, the agent design sweep (dogfooding request #28): capture, every deterministic check, then a model critique per surface (flow state) with zoomed crops of deterministic findings and controls, a measured geometry table (sizes, radii, nearest gaps, contrast, declared component sizes) and, when `design.specFile` names one, the written spec. `spec-mismatch` is a new model category accepted only when a spec is configured. Findings are uncapped (no `model.maxFindings`) and ranked severity first, measured before model; a failing surface degrades the run while keeping the other surfaces' findings. Writes `sweep.json` beside the run; `--emit-tickets <dir>` proposes clustered tickets; `--fail-on` defaults to `never`.

- Added `idiom learn --state <state> "<what's wrong>"`, coaching from misses: a human observation becomes a `checks.components` size, a state size invariant, a `checks.copy.glossary` term or a `checks.mirrored` pair (subjects are resolved to selectors from the state's stored capture, or `--selector`), and anything else a design-law ruling through the ruling machinery (`--ruling`, `--wording`). Each learning appends a provenance line, with the capture it was seen on and an optional `--screenshot`, to `.idiom/learned.jsonl` (commit it). Nothing is written until the exact diff is confirmed (`--yes` skips the prompt).

## [v0.5.0] - 2026-10-23

System conformance completes, and the gate learns what is new. Delivers dogfooding requests #9, #10, #12, #18, #19, #21 and #32, plus clustered ticket proposals (#11), before/after composites (#13) and published-page budgets (#15). Benchmark unchanged: 7/7 before, none after.

- Added before/after composites with `idiom compare <flow> --from <runId> --against <runId>` (dogfooding request #13): a labelled before | after PNG (state, viewport, scheme and both commits) for every tuple whose pixels changed, plus a report of new and fixed deterministic findings. The output uses the `idiom verify` attachment contract, so Autobuild attaches it the way it attaches `before-after.md` today.
- Added published-page budgets with `"kind": "published"` flows (dogfooding request #15): `pages`, widths as viewports (default 1280/768/375) and `budget.maxDiffRatio`. The new `published-budget` check reports horizontal document overflow with the measured width, broken images by URL, serious or critical axe violations and pixel drift from a recorded baseline as blockers, and `idiom review` fails on them. `idiom baseline record` writes the pixel baselines to `<flow>.pixels/` for published flows.

- Added clustered finding proposals (dogfooding request #11): `idiom tickets --cluster` groups accepted findings by observed component and category; `idiom check <flow> --emit-tickets <dir>` proposes current actionable findings without accepting them. Specs retain all member criteria, identities, selectors, verification records and crop links. Member deduplication survives retries and ticket promotion, and file output always enters human triage.

- Added `empty-state` and `progress-affordance` (dogfooding request #10). Empty lists, tables, grids, feeds and declared canvases require explanatory text and a CTA. Configure `checks.emptyState` (`regions`, `auto`, `ignore`) and `checks.progressWithinMs` (default 1000); web mutation steps accept `longRunning`. Capture records optional `emptyRegions` and `progress` evidence for offline review and threshold changes. Earlier captures report unavailable/skipped coverage until recaptured. README and guided init show how to force empty, error and loading fixtures. Progress timing starts at input dispatch, excluding waits for controls to become actionable; empty-state prose and populated items inside `display: contents` wrappers are retained. Progress tracking follows replacement controls and label-to-control fill/select retargeting through live Playwright locators and recognizes running spinners revealed from hidden visibility or opacity. Empty-state explanations may use native or ARIA headings.

- Added compact, committable per-commit finding baselines (dogfooding request #12): `idiom baseline record <flow>` and `check` / `review --since-baseline` separate new, fixed and pre-existing deterministic occurrences, resolve reachable Git ancestry, warn on changed checks configuration, and gate only new findings.

- Added `luminance-parity` and `frame` (dogfooding requests #9 and #32). In light/dark runs, `luminance-parity` reports a surface whose background does not flip while its painted container and comparable neighbours do (the white title input in dark chrome), and any primary-action label under 4.5:1 in either scheme. `frame` reports the configured `checks.frame.selector` when no visible edge shows a fill luminance step (`minLuminanceDelta`, default 0.05), a painted border or a shadow against its real surround, including a pointer-inert canvas sibling. Capture persists composited paint (`signals.paint`) and frame edge samples (`signals.frameEdges`); `checks.luminanceParity.primarySelectors` and `ignore` cover custom primary actions and fixed-colour content. Earlier captures report both checks as unavailable until recaptured.
- Added `primary-region`, `alarm-at-rest` and `cross-surface-naming` (dogfooding requests #18, #21 and #19). `checks.primaryRegion` (`selector`, `minShare` overall or per viewport) reports the region's measured width share in every run and a finding below the minimum. `alarm-at-rest` reports warning glyphs, alert-named icons and red or configured warning colours (`checks.alarm.colors`, exempting `checks.alarm.brand` and `checks.alarm.ignore`) on icons with no error context (aria-invalid, role=alert, status text, an error state id). After a public-site sweep, amber is judged only when it is a configured alarm colour, and the red heuristic applies only to icon-sized, single-hue ink. `cross-surface-naming` compares the labels one `data-node-id` shows across `checks.naming.surfaces` (tree, breadcrumb, chip, toolbar) and reports mismatches as one finding listing each surface's label. Capture records `signals.alarm` on icon-like elements; earlier captures report these checks as unavailable until recaptured.

## [v0.4.0] - 2026-10-23

Flows that move, and the first system-conformance checks. Delivers dogfooding requests #1, #2, #4, #17, #20, #23, #24, #25, #26, #29, #30, #33 and #45. Benchmark unchanged: 7/7 Oct 22 defects before the fix, none after.

- Flows can declare `toggles` and capture their combinations, with layout screenshots deduplicated by signature while retaining every combination’s deterministic evidence, recorded collapse counts and combination-labelled findings (dogfooding request #30).

- Added `element-overlap`, `clipped-text` and `field-group` (dogfooding requests #4 and #25): report intersecting controls/text with selectors and measured overlap, labels clipped without ellipses, and touching or crowded label/control/helper groups. Configure minimum gaps with `checks.fieldGroups.inner` / `.between` (defaults 4px / 12px). Evidence is persisted for offline review; legacy captures show unavailable coverage until recaptured.

- Added action-based `motion` audits for panels, drawers, menus, popovers, dialogs and tooltips (dogfooding request #45). Probe and web-step captures persist actual animation evidence for offline review, with `checks.motion.maxMs`, optional duration scales and custom surface selectors. Reports cover snapped toggles, slow or off-scale effects, and motion running under reduced motion; legacy captures expose unavailable coverage.

- Added `scale-conformance` and `control-anatomy` (dogfooding requests #17 and #26). `checks.scales` declares control heights, corner radius per role (control, card, panel, chip), border colour per role (divider, control) and optional role selectors; each off-scale value is reported once with a count and examples, and without a declared scale only sharp outliers from the run's prevailing value are reported. `control-anatomy` reports select chevrons and icon-button or segmented-control icons more than 1px off the label's ink centre (or the box centre), and sibling selects whose inner padding or chevron size differ. Capture now measures background-image select chevrons (`signals.adornment`); earlier captures report `control-anatomy` as unavailable until recaptured.

- Added the `selected-state` and `dialog-shell` checks (dogfooding requests #20 and #23). `selected-state` reports selection groups with no option selected, several selected in a single-select group, or a selected option that is not visibly different from its siblings; `checks.selectedState.minColorDelta` sets the colour threshold. `dialog-shell` reports open dialogs with a missing or duplicated heading, no visible close control, a primary action outside the viewport without a sticky footer, or a title size that differs from the run's other dialogs.

- Added `mirrored-control`: pairs declared in `checks.mirrored` are compared per capture for size, element kind, type and canvas-facing placement (dogfooding request #24). Hidden accessibility labels and graphics do not affect rendered kind, and pairs sharing a control retain separate finding identities. Visible glyphs in `display:contents` wrappers and generated `::before`/`::after` content retain their type evidence; unsupported generated content reports unavailable coverage for its pair while preserving findings from other pairs.

- Added `disguised-control` (buttons that look like text fields, readonly or disabled fields that look editable) and `fresh-state` (enabled undo/redo and unsaved indicators on states declared `"fresh": true`), with `checks.disguisedControl` / `checks.freshState` configuration (dogfooding request #33).

- dogfooding request #2: web flow states support ordered interactions and assertions, with per-step browser/network/server-log health checks, additive allowances, and failure screenshots in capture and review coverage.

- Added flow and state layout invariants for dimensions, edge alignment, offsets and missing selectors, measured in every capture tuple and replayed from stored observations (dogfooding request #29).

- Added opt-in production capture and check (`--prod`, `server.production`, and flow defaults), isolated port/data/output lifecycles, and persisted build identifiers in check/review reports (dogfooding request #1).

## [v0.3.0] - 2026-10-23

This release answers the first round of dogfooding requests: a human design review found seven chrome defects that idiom 0.2.0 reported none of (#43). Idiom now finds all seven in the benchmark fixtures before the fix and none after, with no new findings on the booking dogfood flow. Item numbers refer to that request list.

### Added

- Added `idiom check <flow>`: capture plus every deterministic check, printed in fix order with done-when criteria, a cropped screenshot, and the decide command; `--json` for agents, `--fail-on` for gates, `--baseline <runId>` to report only new findings (#14, the primitive under #12).
- Added `review --latest` and `check --latest`, which resolve the newest fully passing capture of the flow at HEAD (#14).
- Added eleven deterministic checks: `unexplained-control` (#34), `dead-control` and `duplicate-entry` through an opt-in interaction probe (#39, #35, #33), `dead-affordance` (#40), `adjacent-gap` including focus rings (#38), `text-centering` (#37, #26), `component-size` (#36), `copy-lint` (#3, #22), `glyph-icon` (#27), `error-text` (#42) and `native-control` (#7).
- Added `idiom coverage`, which lists app/pages routes (or crawled links) that no flow captures, and a flow-level `routes` shortcut (#42).
- Added a `checks` block to `.idiom/project.json` (`minGap`, `centeringTolerance`, `components`, `copy`, `glyphAllow`, `errorPatterns`, `probe`), and state-level `viewports` (#5), `focus` and `probe`.
- Added a Craft checks section to `idiom context` and a check mode to the vendored `/idiom` skill, so builders see what will be rejected before they write it.
- Every deterministic finding with a locatable element now carries a crop of it (#44).

### Changed

- `spacing-rhythm` no longer measures rows against the edge of an overflowing scroll container or the fold of a fixed app shell (#6).
- `overflow-clip` reports text inputs as a minor truncated value rather than major clipping, ignores 1–2px single-line overhang, and states the overflow in pixels (#44).
- Framework-generated ids (React `useId`, Radix, Headless UI) no longer anchor selectors, so findings keep their identity across builds.
